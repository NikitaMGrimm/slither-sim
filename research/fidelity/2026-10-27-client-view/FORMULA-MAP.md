# Prediction formula and update-order map

Original source analysis for this offline study. No official source or assets are reproduced.

**C** is [slither-client at `8d0772c`](https://github.com/NikitaMGrimm/slither-client/tree/8d0772c015d6b9b73b80253db8c7349aa600b201).
**S** is [SlitherSim at `aee5421`](https://github.com/NikitaMGrimm/slither-sim/tree/aee542100496b8cbc031b8ab19bb58e78bd8af2b).
All file/line citations below refer to those full revisions, including historical claims that
were inspected as source and were not independently remeasured here. Source-only observations
do not establish a hidden official-server mechanism. Main [report](REPORT.md).

## State and prediction layers

| Layer | Source facts | Consequence |
| --- | --- | --- |

Radius is fixed 6, documented as presentation metadata. `C src/state.rs:829-895,908-924`. | Do not compare its radius to physical hitboxes or use its heading interchangeably with presentation's initial heading. |

## Turn, scale, speed and clocks

Let n be logical/physical segment count, sp wire speed in units per 32 ms, d animation delta, and Q(s)=0.13+0.87((7-s)/6)^2.

| Topic | C presentation | S authoritative |
| --- | --- | --- |
| Size / scang | s=min(6,1+(n-2)/106); scang=Q(s). No lower clamp, so supported logical n=0/1 produces s<1. `C src/presentation/snake.rs:302-308`. | Body scale clamps 1+(n-2)/106 to [1,6]. Turn scale separately clamps 1+(n-2)/111 to [1,6]. Turn rate = .033/.008 * Q(turn_scale). Source labels 111 an empirical fit through 293 segments. `S src/physics.rs:40-57`. |
| Turn integration | Maximum turn=mamu*d*scang*min(1,sp/spangdv). Signed wire direction chooses increase/decrease; target crossing clears direction, exact landing retains it until later crossing. None copies wanted. Turns even after death. `C src/presentation/snake.rs:351-384`; `C src/presentation.rs:289-357`. | Desired input is floor-quantized to 251 headings. Shortest angular difference is clamped to +/- turn_rate*dt, then movement uses the resulting heading. No separate speed factor because normal speed is above divisor; no dead-snake movement/turn. `S src/physics.rs:54-57,149-151,281-297`; `S src/simulator.rs:1578-1584,1698-1705`. |
| Head travel | sp*d/4, capped at one anchor spacing per update; head fraction increases by travel/spacing, not clamped to [0,1]. Normal anchor event explicitly supplies zero extrapolation. `C src/presentation.rs:323-353`; `C src/presentation/client.rs:1903-1915`. | world_speed*dt; no presentation cap. One anchor crossing check per tick. `S src/physics.rs:281-328`; `S src/simulator.rs:1735-1742`. |
| Clock | d=clamp(elapsed_ms/8,0,5)*lag. Lag falls by *.85 to floor .2 per lagging call, recovers +.05 to 1 per nonlagging call. Whole/double steps are differences of accumulated floors. Backward time contributes zero and replaces timestamp. `C src/presentation.rs:123-207`. | Default dt=.007 s; speed unit .032 s and reference coefficient unit .008 s are explicitly separate from tick. `S src/physics.rs:14-24`; `S src/simulator.rs:435`. |
| Reported speed | Appearance u16/1000; snake motion byte/18, divided by .032 only in received view. Presentation retains raw scalar. Cruise=nsp1+nsp2*s, boost threshold=cruise+.1; nsp3 is maximum metadata. No physical acceleration from held boost. `C src/state.rs:815,893,1066-1096,1259-1266`; `C src/presentation/snake.rs:282-285,302-308,377-383`. | Cruise=(5.39+.4*scale)/.032; full boost=14/.032=437.5. Default latent progress changes +.015 or -.02 per .008 s, divided by 1+.305(scale-1), clamped [0,1]; speed recomposed only while progress is moving. Idle cruise can remain below new-size cruise. Alternate direct-speed model approaches target by size-dependent slope. `S src/physics.rs:29-30,50-67,123-146`. |
| Visual boost | Live-call visual speed approaches reported sp with .1 rising/.3 falling plus +/- .0001 and clamp. This occurs even for zero elapsed. Boost phase adds (visual_speed-threshold)*d*.021 only above threshold. `C src/presentation/snake.rs:466-506`. | Boost active eligibility is mass above two segments, with exhaustion latch; mode floor explicitly changes this. First active drop is primed immediately; nominal later interval .155 s. Mass cost .0812*max(0,1-n/430)^1.66 with [.94,1.08) jitter. `S src/physics.rs:31-32,164-170`; `S src/simulator.rs:1603-1652,1685-1696`. |
| Update order | Boundary easing, snakes, prey, food, retire retained objects. Snake live length first; turn/move; eyes; body/head/angle rings; spawn/death fades. `C src/presentation/client.rs:2142-2167`; `C src/presentation/snake.rs:488-531`. | Radius update; capture old heads/tips; for each live snake: speed, boost mass/drop, turn/move, wall/pit, anchor growth, radius/score refresh/kiosk. All snakes finish movement before collision resolution. Then deaths, food pickups, prey, ambient refill. `S src/simulator.rs:1558-1592,1621-1745,1780-1785,1855-1899,1996-2023,2028-2106`. |

Important intra-tick size detail: S captures scale before boost mass loss, updates speed with the old count, uses post-loss count for turning, uses the captured scale for wall contact, then can grow at an anchor before collision/pickup geometry. These are actual phase boundaries, not interchangeable "current size" samples. `S src/simulator.rs:1621-1628,1649-1654,1698-1707,1735-1745,1771-1778`.

## 111 versus 106: calculated count and timing implications

For n>=2 before saturation, Q is injective over the used scale range, so:
- Matching S(n) with C(nc): nc=2+106(n-2)/111; n-nc=5(n-2)/111.
- Matching C(n) with S(ns): ns=2+111(n-2)/106; ns-n=5(n-2)/106.
- These are real-valued equivalents. Actual logical counts are integers.

Calculated directly from the pinned formulas, not measured values. Rate ratios assume equal mamu=.033, equal elapsed time, speed-turn factor 1 and no target landing. Rows above 293 extrapolate the turn fit. A fixed deficit k only matches at n=2+111k/5; k=5 matches n=113, not all sizes. Client scale saturates at 532, server turn scale at 557; at/above saturation the inverse is not unique.

Length's -0.6 end adjustment, one head fraction, and fractional fam are not fed into scang. Dying points can make retained length much larger, but scang reads logical count only. Growth and explicit tail events change count immediately in C; non-growth anchors leave it unchanged. `C src/presentation/length.rs:20-27,42-62`; `C src/presentation/body.rs:253,340-350,376-418`; `C src/presentation/snake.rs:304-305`.

A constant multiplicative clock correction also fails globally: S/C rate ratios run from ~1.00087 at 9 to ~1.05135 at 293. A fixed phase lag changes intercept, not steady slope. Frame clamping, lag multipliers, signed direction, stale speed/heading and correction rings can distort measured rendered arcs; they must be accounted for, but source inspection does not identify them as the origin of 111. Count timing could matter in growth/boost windows; it is not a demonstrated fixed offset.

## Body anchors, corrections, segment/fam timing and length

- **S anchor rule:** once head-to-front distance reaches 42, form a new 42-unit anchor along that ray after floor quantizing direction to 65536 steps. Overshoot is not removed from the physical head. Contract existing body sequentially from index 3, weight .43*min((i-2)/4,1), then insert front, then remove tail for non-growth. `S src/physics.rs:299-328`.
- **C body rule:** reconstruct relative anchor with setup spacing/cached u16 direction or use absolute position; mark oldest living tail dying for non-growth, increment logical count for growth, insert front, then contract index 3 onward with setup contraction*min(i-2,4)/4. Each point follows its already-moved neighbor, including dying records. Thus S's old index 3 moves before it becomes new index 4; C's old index 2 moves at new index 3. `C src/presentation/body.rs:281-367`.
- **C body interpolation:** 53 f32 cosine-weighted correction samples across x/y/edge/spacing, subtracting each displacement from pending samples; visible-only anchor/contraction injection. New anchor starts projected from the prior displayed front toward the pre-event corrected head; contraction does not refresh edge-length channel. Spacing table is 1-contraction*clamp(index-3,0,4)/4. `C src/presentation/body.rs:35-78,227-234,308-365`.
- **Head correction:** new anchor resets fraction to extrapolated_distance/spacing (normal execution zero), injects positional jump and fraction-(old_fraction-1); 53 f32 samples refresh current offsets immediately. Heading jumps use shortest signed angle, 26 f32 samples, with current offset updated only on later positive whole-step advance. Rendered head/heading add these offsets. Neither offset steers raw prediction. `C src/presentation.rs:255-286,370-424,434-484`; `C src/presentation/snake.rs:638-652`.
- **Retained tails:** explicit removal decrements logical count once and marks oldest living point dying. Positive whole steps add .0015*steps to dying fade; fully faded fourth-and-older dying records are erased; three newest dying records persist. This is not simulator physical body count. `C src/presentation/body.rs:372-418`.
- **Mass lifecycle:** S food/prey pickups only add fam after movement/collision. Only a later crossed-anchor event consumes one whole fam, adds one segment and keeps tail; at most one such growth per tick, even if fam remains >=1. Boost loss can remove multiple segments immediately and truncates physical tail before movement. `S src/simulator.rs:1647-1652,1735-1743,1996-2023,2512-2513,2716-2720`; `S src/physics.rs:424-439`.
- **Wire lifecycle:** fam encoding clamps to [0,1], round to u24; thus any pending S fam>1 is not directly visible as continuous raw mass. Host usually emits tail removals, standalone mass if due, motion if due, then anchors (growth carries fam); this is a host release order, not proven universal server order. Full appearance sends exactly physical body count using one absolute tail + intermediate deltas + final directed front. `S src/client/encode.rs:81-82,188-245`; `S src/client/simulation/snakes.rs:365-418`.
- **C length/size:** fam-only updates schedule length but do not change scale. Growth updates body, recomputes size, schedules length, then reanchors head; tail packets schedule length and recompute size if removal found. Displayed length=target+f32 correction-.6, target=n+min(fam,1), independent of scang. Ring advances only on live updates. `C src/presentation/snake.rs:389-445,508-521`; `C src/presentation/length.rs:20-62`.
- **Draw spacing:** target=max(6*scale,4.5/zoom), approached +/- .0035 once per visible draw, independent of elapsed. Curve uses corrected head, normalized edges/spacing and displayed length; rendered width derives from 29*scale, not received radius 6. `C src/presentation/snake.rs:308,538-554,575-591`; `C src/presentation/curve.rs:14-29,357-417,529-539`; `C src/presentation/body_painter.rs:783`.
- **Score:** at table size 430 both use factors (1-min(i,429)/430)^2.25 and accumulated reciprocal factors, then floor((sum[n]+min(fam,1)/factor[n]-1)*15-5). C accepts setup table size and plateau extension; S caps score index at 430. Own R credit composes a scoring index, not physical size/scang. `C src/presentation/score.rs:47-73,95-112`; `S src/physics.rs:331-353`; `S src/client/protocol.rs:1614-1619`.

## Food generation, filtering and animation

- C decodes sector offsets using advertised sector size/256 and sizes byte/5; presentation keeps absolute position, while received map is centered and unique-key. Presentation can retain duplicate lifetimes independently. Food clear-sector commands remove recipient state, including consumed instances; they do not establish global deletion. `C src/state.rs:1112-1141,756-766`; `C src/presentation/food.rs:449-503`.
- C uneaten food is visually displaced by a 6-unit sin/cos wobble, animation rate .65+.1*size and independent wobble rate (2u-1)*.0225. Spawn fade grows rapid_factor*d/150 (factor 3 rapid, otherwise 1), with nested cosine easing. Nominal full fade is 400/1200 ms. Consumption grows d/41 (328 ms), uses k=p^2, scale=prior_scale*(1-p^3), interpolates toward corrected eater mouth at (43-24k)(1-k) and shrinks wobble by 1-p. These are draw positions and visual times, not physical food paths or delayed authoritative nutrition. `C src/presentation/food.rs:399-423,533-596`.
- S food stays at a stationary quantized physical position. Grid spacing is 300/256. Physical pickup circle leads head by speed*.032*(7.55+1.8*(scale-1)), radius 36+19*(scale-1); selected with postmovement pose, reverse food order, nearest-head/lexical-id ties. Nutrition=size^2*.0031535*max(1-(n+fam-2)/430,1/430)^2.25 and changes with mass within a segment. `S src/physics.rs:153-184,441-442`; `S src/simulator.rs:1894-1904,1996-2008,2826-2853`.
- S modeled global target=floor(7*pi*radius^2/300^2), ambient attempt rate=.1024*pi*radius^2/300^2. New ambient radial-area proposals sqrt(u) are accepted against .217-.172*f; radius extent=max(radius-20,0), size rounds (3+6.4u) to .2. Source explicitly labels radial profile provisional. Refill credit accrues after pickups; new ambient food cannot be picked up in that same tick. `S src/simulator.rs:334-345,1011-1031,2028-2106`.
- Admission caps all existing food origins in 75-unit cells: ambient 2, boost 9, death 22. This is a candidate admission rule inferred from received occupancy; it cannot separate actual generation from delivery filtering. `S src/simulator.rs:25-38,55-68,85-98,1665-1681,2083-2101,2615-2630`; `S docs/server-rules.md:55-60`.
- Boost pellet size=floor(5*sqrt(.95*cost/(nutrition_coefficient*mass_multiplier)))/5; placement jitters previous tail by captured scale*16 full width. Death candidates comprise head plus two sites per physical anchor (midpoint and point), scatter +/-15*scale, size rounded to .2 from 13.6+1.375e-7*n^3; admission/mode filtering can reduce 2*n+1. `S src/simulator.rs:1640-1657,2580-2630`; `S src/physics.rs:447-465`.
- Host food subscription is distinct: 7x7 sectors minus four corners, led 100 units along physical heading, touched before cleanup; retention 2.6 s, cleanup opportunities .504 s. Ambient births are revealed on shared maintenance; boost/death are prompt. Sector departure clears recipient food without deleting world food. No C fade/wobble can identify this generation/filter split. `S src/client/visibility.rs:1-16,37-78,105-118`; `S src/client/simulation/food.rs:157-164`; `S src/client/simulation/broadcast.rs:318-326`; `S docs/server-rules.md:87-89`.

## Scheduler, radius, wall and collision implications

- **Scheduler:** preserve server elapsed time, receipt time, presentation timestamp, raw packet order, and update/draw order separately. C stores elapsed headers but does not advance animation from them; normal snake/prey packet reanchors have zero extrapolation. S bot receiver accumulates header intervals as server time (setup resets origin), while raw framing uses receipt-relative time. `C src/state.rs:559-564`; `C src/presentation/client.rs:1911-1914`; `C src/presentation/prey.rs:389-395`; `S src/client/protocol.rs:825-851`.
- Host shares per-snake report gates: 6 ticks motion, 15 ticks standalone fam; responsive delivery bypasses changed wanted/speed and changed fam. Body anchors are not on those report gates. Prey corrections use 1/3 s or .210 s if current/last reported speed encodes exactly 11. These are existing host models. The retained scheduler report explicitly finds short-gap and reverse-order exceptions and selects no replacement law. `S src/client/simulation/snakes.rs:15-33,169-186`; `S src/client/simulation/broadcast.rs:515-535`; `S research/fidelity/2026-10-26-movement-scheduler/REPORT.md:3-16,126-156`.
- Host ingests arrivals through tick end before world.step, and threaded scheduling drains commands before each fixed tick; catch-up is bounded to 8 ticks/pass and .25 s backlog before deferred-world-time handling. C's .040 s per-call animation clamp must not be used as host tick or catch-up rule. `S src/client/simulation/broadcast.rs:193-230`; `S src/client/server.rs:98-101,635-686`.
- **Arena radius:** C accepts setup/target radius; separately displayed radius eases through 56 f64 absolute samples, advancing only on connected whole steps. No population controller is inferred. S ordinary seat target=670*sqrt(max(occupied,1)), with 3% dead zone, immediate expansion and 23.4375 units/s shrink; recorded radius trace overrides at tick end. Custom circular modes have separate seat scaling. This is explicit product policy. `C src/state.rs:774-778,1237-1240`; `C src/presentation/boundary.rs:31-95`; `S src/simulator.rs:370-380,745-753,2117-2162`.
- **Wall sliding:** C's inspected head predictor does no wall constraint. S uses a scale*16 forward contact point; if head center is outside, lethal; if contact projects outward beyond sin(.7), lethal; otherwise radially project contact to arena and subtract forward lead, retaining heading. This is a calibrated constraint, not recovered hidden mechanics; compare against authoritative anchors and target radius, not eased boundary plus corrected head. `C src/presentation.rs:323-354`; `S src/boundary.rs:15-65`.
- **Collision:** C presentation has no authoritative death solver in inspected paths. S probes from old head tip to new tip extended by target body's radius, with near-point cutoff .975*body_radius and broad phase 3.666 summed radii; line is other tip -> head -> anchors. S moves all snakes then resolves old joins first against newer first, skipping already fallen snakes; boundary deaths win their phase, then death food is available before ordinary pickup. This geometry/order is client-derived for offline play; official online move/test phase remains unverified. `S src/physics.rs:188-254`; `S src/simulator.rs:1780-1803,1813-1848,1863-1904`; `S docs/server-rules.md:55,209-212`.
