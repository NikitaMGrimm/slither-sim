and `docs/` for current commands/behavior. This archive holds dated studies and
selected results, including rejected and inconclusive attempts. Collection or
archive integrity establishes neither scientific rules nor product adoption.

| Performance | [Live Battledome after the spawn-search fixes](performance/2026-10-29-battledome-post-spawn/REPORT.md) | Repeats the constant-boost socket rows on one c7a.medium core, comparing main before #272 with main after #273, one window per version. At 320 players both still fall behind, the candidate for 66 ticks against 231, with lower CPU p99 (12.8 against 13.9 ms) and jitter. At 480 both are badly overloaded and the results are mixed. Spawn search still takes 61% and 57% of the candidate's slowest ticks at 320 and 480, and sockets and broadcast most of the rest. 640 was skipped. All attempts cost at most $1.38. |
| Performance | [Compact occupied snake histories](performance/2026-10-29-compact-snake-history/REPORT.md) | Each player's snake history keeps only occupied records in one sorted vector, with byte-identical output. Fully grown 500-player ticks use 14% (stock) and 18% (protocol 13) less CPU, and reserved history memory falls from 20.44 MB to 0.445 MB. The study rejected the change under its frozen 2% small-world limit (about 70 ns more per tick at one player and 1.6 µs at 50 protocol-13 players); the maintainer adopted it after the results because that cost is negligible against a 7 ms tick. No timing retry or tuning. |
| Performance | [Exact lazy head edge blocks](performance/2026-10-29-spawn-head-blocks/REPORT.md) | Spawn searches skip groups of eight body edges that are provably out of reach, building each group's bounds only when a search first reaches that snake. Five alternating pairs per protocol on AWS keep a 63.18% instruction saving in a synthetic overload where every search fails, and CPU p99 falls from about 1.46 to 0.64 ms. In 80- and 160-player controls, instructions and successful-search CPU match main, apart from a 1.3% higher p99 with protocol 13 at 160. A first version that built every group up front doubled the cost of preparing each respawn and is kept as a rejected attempt. No live-capacity claim. |
| Performance | [Exact head distances in spawn searches](performance/2026-10-29-spawn-head-distance/REPORT.md) | Spawn searches check head clearance with the existing exact distance comparison instead of always computing `hypot`; every verdict and output byte is unchanged. In a synthetic AWS overload where every search fails, instructions fall 40.46% and CPU p99 drops from about 3.3 to 1.6 ms with both protocols. Ordinary 80- and 160-player controls run the same instructions, but median tick CPU is 4–17 µs higher, which the study could not attribute. No live-capacity claim. |
| Performance | [Simulation memory diagnostic](performance/2026-10-29-simulation-memory/REPORT.md) | Measures cache and address-translation misses on the simulation thread in a fully grown 500-player world, with both protocols and no sockets. The strongest portable lead is the per-player snake history: it reserves a slot for every snake (20.38 MB in total) to hold 176.7 kB of snakes each player actually knows, and those paths take 44% of ordinary-tick dTLB-miss samples. Food and subscription paths dominate food-update ticks. L2/LLC and pipeline metrics were unavailable on the test machine, so this does not show that the thread is memory-bound overall or explain the earlier IPC drop. No runtime change. |
| Performance | [Gateway pass costs](performance/2026-10-29-gateway-pass-cost/REPORT.md) | Breaks down the socket thread's CPU with 500 real sockets in a fully grown world: about 3.3 ms per food-update tick and 2.2 ms otherwise, mostly the sends themselves. Polling every connection on each pass costs 0.27 and 0.16 ms, the largest removable piece. An epoll version keeps all traces and both fully grown wire histories byte-identical, but both live series stopped at their frozen background-CPU gates, the second after one qualified pair (socket-thread CPU 3.7% lower, world p99 0.44% higher). The five-pair bar was not met, so epoll is rejected for good, alongside the 2026-10-27 study; the code is kept as a patch. |
| Performance | [Battledome live recheck after the spawn and minimap fixes](performance/2026-10-29-battledome-live-recheck/REPORT.md) | Repeats the constant-boost Battledome rows with real sockets on one c7a.medium core, comparing main with and without #265 and #266. At 160 seats neither version falls behind (CPU p99 3.43 against 3.21 ms). At 320 both do (749 against 434 deferred ticks); spawn searches still take 63.8% of the candidate's slowest ticks, and sockets and broadcast 29.2%. One window per version and seat count, separately evolving worlds and a bot-machine change limit causal claims. 480 was not measured because the AWS session expired. All attempts cost at most $2.97, and the final scan found nothing left in any enabled region. |
| Performance | [Exact pit minimap cache](performance/2026-10-29-pit-minimap-cache/REPORT.md) | Battledome's pit minimap reuses its outline mask while the pit's projected radius stays inside the exact range that keeps every cell's classification. Output is byte-identical across all traces with both protocols. In a synthetic 80-viewer world without sockets, warm minimap ticks run 52.1% fewer instructions (about 0.6% over all ticks), and building the mask costs 12.7% more on that tick. Minimap CPU time falls, but overall p99 ranges overlap, so no live capacity gain is claimed. |
| Performance | [Skip blocked spawn rings](performance/2026-10-29-spawn-ring-prefilter/REPORT.md) | Battledome spawn searches skip building a candidate ring body when its head is already blocked, except in the waiting-join fallback window where rejected candidates still compete. Candidate poses, random draws, errors and admission rules are unchanged, and all traces are byte-identical. In a synthetic overload with 72 waiting joins, where every search tries all 4,096 candidates, total instructions fall 36.7% with both protocols. The fixture has no sockets, so no live capacity gain is claimed. |
| Performance | [Reuse unchanged held food listings](performance/2026-10-29-food-packet-bytes/REPORT.md) | When a player's view moves, keeps the existing reference to each unchanged food sector instead of dropping and re-taking it. Output is byte-identical across all 27 traces and both fully grown wire histories. In a fully grown 500-player world, food-update ticks run 0.23% fewer instructions with stock clients (0.12% with protocol 13), and other ticks slightly fewer. CPU-time ranges overlap, so no live gain is claimed. Two attempts to share encoded food packets between players ran more instructions and are kept as rejected patches. A separate short eight-client trace found exactly one kernel send per TCP write and none for empty flushes; socket code is unchanged. |
| Performance | [Skip unexpired sector cleanup](performance/2026-10-29-subscription-cleanup/REPORT.md) | Tracks each player's oldest retained sector outside their current view and skips the cleanup sweep until that one can expire, keeping the original strict expiry test. All 27 traces and both fully grown wire histories are byte-identical. In a fully grown 500-player world, food-update ticks run 3.74% fewer instructions with stock clients (3.52% with protocol 13); other ticks run about 0.15% more, so total work rises by about 0.03%. CPU-time ranges overlap, and no live capacity gain is claimed. |
| Performance | [Battledome with constant boosting](performance/2026-10-29-battledome-boost/REPORT.md) | Repeats #262 at 80, 160 and 320 real socket bots with the same host binary, keeping A4's steering but making the bots boost 99.7–99.9% of the time. At 80, play stays smooth (p99 jitter under 1 ms, no deferred ticks). At 160 spawn searches cause occasional slow ticks (worst 9.8 ms). At 320 the server falls 705 ticks behind in the measured window and 95% of respawns take up to 1.23 s; spawn searches take 61.8% of the slowest ticks. The worlds evolve separately, so the comparison with #262 is descriptive. One server pair cost about $0.11, and cleanup found nothing left in any enabled region. |
| Performance | [Shared food diffs on the food-update tick](performance/2026-10-29-food-diffs/REPORT.md) | Computes each sector's food changes once per broadcast and shares them with every player holding the same previous listing; players with older views keep the old path. Output is byte-identical across all 27 traces and both fully grown wire histories. In a fully grown 500-player world, food-update ticks run 7.55% fewer instructions with stock clients (6.84% with protocol 13), and 1.1% fewer over all ticks. The CPU-time drop is smaller than the timing noise, and the live 500-socket confirmation is incomplete because its last control window drifted outside the length class. A separate diagnostic ranks what remains on that tick: socket writes (2.76 ms), per-player food packet copies (1.74 ms), snake visibility and encoding (1.01 ms) and sector cleanup (1.00 ms). |
| Performance | [One-core Battledome experience](performance/2026-10-29-battledome-experience/REPORT.md) | Runs real WebSocket bots from a second machine against one c7a.medium core in Battledome, from 80 to 640 players. At 80 the median tick takes 1.12 ms (worst 3.27 ms) with sub-millisecond jitter; up to 320 the worst tick stays at 7.45 ms, with no stalls and respawns within 20 ms. At 480 the p99 tick reaches 8.77 ms and frame delays grow; at 640 spawn searches take 61% of the slow ticks and the server falls 5,470 ticks behind. Ranked exact fixes: spawn searches, socket writes and broadcast, the pit minimap, then shrinking-pit markers. The bots boosted only 3–5% of the time, so constant-boost human play is untested. Four server pairs cost about $1.72, failed attempts included, and every resource was removed. |
| Performance | [One-core c7a.medium socket ladder](performance/2026-10-29-c7a-mature-capacity/REPORT.md) | Runs real WebSocket bots from a second machine against one c7a.medium core, starting from fully grown snakes and adding bots in steps. It hit its preset 750-bot limit at 6.41 ms median and 9.93 ms p99 per tick with no deferred ticks, so the 6.8 ms point was not reached. The p99 first passes 7 ms between 500 and 550 bots. Bots added during the climb start small, so the top steps have younger snakes (p90 length 116–132 against 181–187 at the start). The human player's windows are labeled, and every cloud resource was removed. |
| Performance | [Mature 500-socket capacity checkpoint](performance/2026-10-28-capacity-checkpoint/REPORT.md) | Puts 500 real WebSocket players with fully grown snakes on one host core and compares the host before and after #249–#255. The median tick takes 4.3–4.9 ms of the 7 ms budget (5.0–5.2 before), but the slowest 1% take 8.8–9.2 ms, and 88–98% of those are the food update every 504 ms. The speedups cut the simulation thread's instructions by 58% but its CPU time by only 32%, as instructions per cycle fell. Socket writes cost about 2 ms per tick, mostly in the kernel. Next targets: the food-update burst, then socket writes. |
| Performance | [Verified body-block reuse](performance/2026-10-28-verified-bounds-reuse/REPORT.md) | Keeps each snake's body-block bounds between ticks and reuses them only when every body coordinate is bit-identical, rebuilding after any change. Output is byte-identical. On top of #253, the fully grown 500-player world runs a further 10.9% fewer host instructions (10.6% with protocol 13); short snakes run 0.6–1.0% more. Building the bounds drops from 1.55M to 0.32M instructions per tick. The remaining cost ranks: visibility checks (2.31M), collision queries (2.20M), then encoding and history (1.26M). |
| Performance | [View-circle body block rejection](performance/2026-10-28-circle-body-coverage/REPORT.md) | Also skips body blocks whose box lies inside the square around a player's view but outside its circle. Reusing last tick's block bounds after checking every body point saved 9.8% in the same trial and landed separately in #255. The remaining cost ranks: visibility checks (2.36M instructions per tick), collision queries (2.20M), then building the block bounds (1.55M). |
| Performance | [Mature host body coverage bounds](performance/2026-10-28-mature-covered-bounds/REPORT.md) | Builds a 500-player world with fully grown snakes by running the full host from tick zero, so food history exists naturally. ## Adding or updating material

- Update the existing `docs/` guide for command, API or explanation changes;
  routine fixes usually need no research report.
- For a distinct study, use `research/<topic>/YYYY-MM-DD-<question>/REPORT.md` and
  link it here. One report should contain question, methods, source/build pins,
  outcomes (including failure), limits, decision and reproduction/evidence links.
  Study amendments can stay together; a PR or agent turn is not a new study.
  Preserve frozen plans and historical conclusions.
- Put only useful, bounded result data beside the report: the values it cites
  and enough to recompute its tables, not every raw sample. Reuse the existing
  [evidence bundle format](../docs/evidence-format.md); do not add a parallel
  claims/status registry. Keep small regressions in `tests/fixtures/`, reusable
  tools in existing `tools/` paths. Source-snapshot tools do not automatically
  archive this tree.
- Keep a patch only for code that does not land: measurement harnesses,
  instrumentation, and rejected or losing prototypes. Squash merges keep only
  the landed change, so such a patch may be its only copy. Code that lands in
  the same PR needs no patch; cite the PR or commit.
- Link an earlier study's scripts instead of copying them, and keep only what
  this study changes.
- Keep raw recordings, full traces, checkpoints, binaries and changing handoffs
  outside Git. When sharing is permitted, give a retrievable URL and digest;
  otherwise label access local-only, restricted or unavailable. Paths/hashes
  identify material without making it downloadable. Historical paths in selected
  JSON are original provenance, not relative file links.

SlitherSim owns simulator/protocol fidelity and simulator/client performance.
Arena owns policy, reward, planner and training/evaluation research, consuming
SlitherSim as a dependency. Do not copy private Arena data here.
Import manifests stay at their historical `docs/` paths.

`research/` is excluded from the Rust crate; packaged guides use repository URLs
to remain usable without the archive. No research framework or extra dependency
is required.
