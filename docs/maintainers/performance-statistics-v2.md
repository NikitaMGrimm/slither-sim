# Performance comparison protocol v2

Adopted 2026-10-25 for new runs. This is an advisory, conditional procedure,
not established hosted-runner calibration, a power guarantee or a runner choice.
Windows, one block per fresh process and the ±5% time band remain unchanged.
The frozen [v1 contract](https://github.com/NikitaMGrimm/slither-sim/blob/main/research/performance/2026-10-24-pr-comparison-statistics/STATISTICS-CONTRACT.md)
still describes historical runs. Never upgrade an in-flight v1 run or reinterpret
its intervals with these constants. New plans use `slither-perf-sequential-v2`.

## Covered looks and allocation

Keep v1's paired log-ratio regression with its fitted order effect, residual
floor, strict Faster/Slower boundaries and inclusive Within boundaries. Retain
its input validation, warmup, failure and latest-covered-prefix rules. Change
only the predetermined schedule, error allocation and operational budget here.

There are ten reserved workload slots and fourteen possible inference looks:
8, 12, 26, then `26 * 2^k` for k = 1 through 11 (52 through 53,248).
The two-sided noncoverage allocation is 1/750 at each of the first three looks,
then `1 / (1000 * 2^k)` at each later look. Every allocation is fixed before the
first sample. Missing or resolved rows lend no allocation to other rows.
The total across all slots is exactly 0.0499951171875, below 0.05.
The union bound therefore retains at least 95% simultaneous coverage under the
independent normal, constant-variance log-error model with constant change and
order effects. Drift, heterogeneous hosts, dependence and changing order effects
can invalidate that model; this extension does not establish those assumptions.

Use Student t with n − 2 degrees of freedom and upper tail `eta / 2`.
The [critical table](https://github.com/NikitaMGrimm/slither-sim/blob/main/tools/fixtures/perf-statistics/protocol-v2-critical-values.csv)
is hardcoded in `tools/perf_stats.py`, generated by SciPy 1.18.1 and independently
checked against the standard-library incomplete-beta tail (relative tolerance
2e-10). Production and ordinary tests require no new numerical dependency.
The table's SHA-256 is
`de2f7e7c0c5a0c00faa09a5c764dcbec9b4fe0192cdaa16bc032f6ffbf4c5303`.
The v2 synthetic OLS oracle, generator and locked script environment live beside
that CSV; v1 references remain unchanged.

Repeat v1's exact literal 26-element order block through the final planned
count. Every adjacent two-pair block and every inference prefix is balanced.
Resolved rows stop immediately. Unresolved rows continue until the time cap or
the explicit 53,248-pair safety guard; reaching that guard is not confidence.
The guard is far beyond the pilot's affordable counts, not a calibrated optimum.
A cap at 45 or 51 completed pairs uses n=26; at 100 it uses n=52; at 5,000 it
uses n=3,328. Later successful unscheduled pairs remain raw evidence. Failed
attempts are never replaced, selected away or retried in the same run.

## Time and publication

The provisional job cap is 1,800 seconds. Before warmups, set the single shared
deadline to `min(stage_start + 1500, job_start + 1800 - 90)` using monotonic
clocks. Builds precede the stage. Reserve 90 seconds for report finalization and
uploads; neither checkpoint pauses nor clock conversion extends the deadline.
An expired child is killed/reaped and retained as a partial attempt. A normal
cap keeps the latest covered prefix. Unexpected sampler or binary validation
failure invalidates affected final claims, including earlier interim claims.

Inference looks and publication checkpoints are separate. At most the first
three covered, complete round checkpoints produce immutable interim snapshots;
a terminal snapshot always follows when report generation completes. Timing is
paused during checkpoint uploads. Pause durations are retained and consume the
same deadline. These interruptions change the measurement process; their impact
has not been calibrated. Sampling stops once every row is resolved/unavailable,
without waiting for unused publication slots.

The [reporting guide](pr-reports.md#publishing-and-permissions) describes trusted
publication, failure withdrawal, postmerge identity and release consolidation.
